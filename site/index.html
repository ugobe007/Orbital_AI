ARIA · Edge

The agent on the floor

Runs on the robot network, hardware-bound and air-gapped. Overhead cameras give ground-truth pose; ARIA corrects onboard SLAM drift toward zero every tick and halts locally the instant it's unsafe.

  • › Camera-based visual navigation, no SLAM reliance
  • › 10 Hz drift-correction control loop (TF-hijack)
  • › Local safety-halt E-Stop with auto re-convergence
  • › Outbound-only mTLS sync to Orbital AI Cloud
Facility network · defense in depth

Robot Harness · Digital Net v0

One repeatable job. A Golden Run for every job after it.

Digital Net v0 is the robot harness — first specified as R4R Harness v0. A lightweight frame of telescoping poles and crossbars puts numbered camera positions around the workspace. v0 runs eight synchronized cameras on a scaffold with 16 addressable positions, ready to expand to 8–16 RGB, IR, and depth nodes. External observations sync with robot telemetry on ARIA.

Frame

Deployment frame

Four corner poles with crossbars. Numbered positions, quick mounts, and cable channels so the sensing volume goes up around a deployed robot.

Sensors

8–16 synchronized nodes

v0 starts with eight synchronized cameras. The frame addresses 16 positions, so the same scaffold expands to RGB, IR, and depth around the workspace.

Calibration

Markers, then self-calibration

Fiducial markers define the sensing volume. A self-calibration process is part of the v0 design, so the volume can be re-established on the floor.

Baseline

Golden Run

Record one successful Golden Run of a repeatable robot job. Every later run is compared with that reference for accuracy, recovery, and drift.

Measure

Deployment Deviation Engine

Detect abnormalities, deviations, recoveries, and changes in task accuracy against the Golden Run.

Sync

Robot Job State Model

Synchronize camera observations with robot telemetry, inference, and task outcomes on ARIA. The result is a labeled deployment dataset for foundation-model training.

How it works

Connect, observe, control

Three phases — from API onboarding to live ops. Orbital becomes the layer between your robots and the humans (or automations) running them on real floors.

01

Connect the fleet

Onboard an OEM through the API wizard. Pick ROS2, gRPC, or REST — grant exactly the scopes Orbital should hold, nothing more.

Outcome: robots appear on the spatial map with live telemetry.

02

Observe everything

Fleet status, mission sequences, drift alerts, and ARIA camera-tracked ground truth — one dashboard, every robot, every OEM.

Outcome: operators see what each robot is doing right now.

03

Take control

Set visual waypoints, dispatch missions, or E-Stop — every command passes scope gates and ARIA's safety-halt before it reaches hardware.

Outcome: governed interventions without bypassing OEM policy.

Every step is scope-governed and logged. Nothing reaches hardware without passing both Orbital's API gates and ARIA's safety-halt controller.
