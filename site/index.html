ARIA · Edge

The agent on the floor

Runs on the robot network, hardware-bound and air-gapped. Overhead cameras give ground-truth pose; ARIA corrects onboard SLAM drift toward zero every tick and halts locally the instant it's unsafe.

  • › Camera-based visual navigation, no SLAM reliance
  • › 10 Hz drift-correction control loop (TF-hijack)
  • › Local safety-halt E-Stop with auto re-convergence
  • › Outbound-only mTLS sync to Orbital AI Cloud

How it works

Connect, observe, control

Three phases — from API onboarding to live ops. Orbital becomes the layer between your robots and the humans (or automations) running them on real floors.

01

Connect the fleet

Onboard an OEM through the API wizard. Pick ROS2, gRPC, or REST — grant exactly the scopes Orbital should hold, nothing more.

Outcome: robots appear on the spatial map with live telemetry.

02

Observe everything

Fleet status, mission sequences, drift alerts, and ARIA camera-tracked ground truth — one dashboard, every robot, every OEM.

Outcome: operators see what each robot is doing right now.

03

Take control

Set visual waypoints, dispatch missions, or E-Stop — every command passes scope gates and ARIA's safety-halt before it reaches hardware.

Outcome: governed interventions without bypassing OEM policy.

Every step is scope-governed and logged. Nothing reaches hardware without passing both Orbital's API gates and ARIA's safety-halt controller.
